# v4 決定事項と操作方式の設計（2026-10-27）

## ユーザー決定
- 採用：質問を打ち終える前にAIが関連資料を先に並べ始める（予測的準備）。
- 採用：AIの思考表現は点滅ではなく「細い線が呼吸するように明滅」。
- 不採用：眼鏡の反射。
- 検討指示：キーボードではなくディスプレイのタッチ操作、AIとの音声会話「風」、手元のタブレットからスライドしてデータを連携。

## 操作方式の設計案

### 1. タッチ操作
- ディスプレイは机上の大判フラット画面を20度ほど寝かせた製図台型（手が届く・平面のまま・四隅が見える）。壁面は立ったままタッチ。
- 机からキーボード・マウスを撤去。UIはカーソルなし、タップ位置に淡いリング、スワイプで一覧をスクロール、長押しで根拠表示。タップ対象を大きく。
- 制作順序：人物クリップ（H3）を先に生成し、指が画面に触れるフレームを読み取ってからRemotion側の反応タイミングを合わせる。人物→画面の順。
- 手は画面色キーで残す（既存の `--key`）。開始フレームでは手を画面の手前に上げた状態から始めると、H3が手を画面に「埋める」失敗が減る。

### 2. 音声会話「風」
- 人物は声を出さない方針を維持（発話は入れない）。口元が見えない構図（背後・肩越し・口元が画面外）で「話しかけている」ことを示す。
- 画面側で会話を表現：下端の細い線が声に反応して波打つ（聞き取り中）→ 質問文がライブ文字起こしで現れる → 線が呼吸に変わる（思考中）→ 回答がストリーミング → 線が一定の明るさに落ち着く。
- AIの音声は入れない（ナレーションと競合する）。応答開始の柔らかい上昇音1つだけ。
- 同じ線が「聞く・考える・答える」を一本で表す。これがv4の視覚的な主題。

### 3. タブレットからのデータ連携
- タブレットは机上に平置き（固定四隅で合成できる）。監査人が資料カードを指で上方向にスワイプ。
- カードはタブレット上端から消え、大画面の下端から現れて「受領資料」に収まる。中間の飛行は合成時の2Dオーバーレイ（タブレットの上端→モニターの下端、0.5秒、モーションブラー）。
- 合成は2面（モニター四隅＋タブレット四隅）。手の遮蔽はそれぞれの画面色キーで処理。
- チーム共有（P3）でも同じ所作：タブレットを壁面に向けてスワイプ→壁面に展開。

### 4. 開始フレームへの影響
- P1〜P5は撮り直し（キーボードなし、製図台型ディスプレイまたは壁面、机上に平置きのタブレット、手の位置）。
- 口元が見えない構図を優先。正面顔のカットは「聞いている」瞬間だけに限定。

### 5. 呼吸する線の仕様（Remotion）
- 高さ2px、幅は画面の対話領域いっぱい、色はティール。
- 思考中：不透明度 0.35→0.85→0.35 を2.4秒の正弦で、わずかに横幅も伸縮。
- 聞き取り中：架空の音量包絡で振幅が変わる（線が細かく波打つ）。
- 回答中：一定の明るさ。完了：0.4秒で淡くなり残る。
- 同じ線を、壁面の「AI記録中」、翌朝の「夜間再分析」、報告画面の「同期中」にも使い、映像全体のモチーフにする。
