# リポジトリ街の夜勤 — 5分04秒実験シナリオ

## 実験の目的

- 8秒の独立シーンを38本つなぎ、5分04秒の動画として破綻なく再生・書き出しできるか確認する。
- 直近で更新された5つのGitHubリポジトリを、ひとつの街で働く人物として擬人化する。
- 技術の列挙ではなく、記録から説明までが循環する物語として内容を理解できるようにする。

## ナレーション原稿（7章）

### 01 Prologue（00:00–00:24）

午前零時。人が眠りにつくころ、リポジトリ街では、今日の変更が静かに動き始めます。ここに暮らすのは、直近で更新された五つのリポジトリ。それぞれ別の仕事を持ちながら、記録、設計、データ、検証、そして説明を、ひとつの循環へつないでいます。今夜は、その住人たちの仕事をのぞいてみましょう。

### 02 my_work（00:24–01:04）

最初は、記録係のミオです。毎朝六時、日次レビューの白紙を用意し、入力したニュースや学び、思いついたアイデア、終えたタスクを、迷子にならない場所へ並べます。ここでは、プルリクエストそのものが仕事の足跡です。何を始め、何を終え、どんな判断をしたのか。今日の行動が履歴として残るから、週末の振り返りは記憶頼みになりません。ミオの仕事は地味に見えて、街全体の時間をつなぐ基礎になっています。

### 03 App_Idea（01:04–02:16）

次は、設計士のアイ。彼女の机には、PDF、CSV、Excel、画像が次々と届きます。目標は、散らばった証跡を、レビューできる一枚のエビデンスシートへ変えること。まずS1が、要素の契約とDrawingMLによる描画の土台をつくります。次にS2が、文書や表から必要な箇所を決定的に取得します。見つからない範囲を、それらしく推測することはしません。未解決として警告し、人に判断を返します。画像では、Visionが広く探す一回目と、拡大して確かめる二回目を分けて範囲を特定。直近の精度検証では、十四件すべてを検出し、十二件が受入基準を満たしました。そしてS3が、何をどこに置くかを計画し、取得結果と引用を結び、シートへ組み立てます。派手な一枚の裏には、推測を避け、根拠を落とさないための小さな約束が、何層にも積み重なっています。

### 04 demo_data（02:16–03:04）

その設計を試すには、現実に近い資料が必要です。資料管理官のデータが守るのは、架空の上場製造業、デモA株式会社。販売、購買、在庫、IT、決算まで、五十三の統制と評価資料がそろっています。中には、真の不備、追加証跡が必要な判断保留、業務影響の小さい例外も、意図的に混ぜられています。さらに直近では、四社の連結パッケージを回収し、内部取引の照合、在外子会社の換算、消去仕訳、連結精算表、連結財務諸表までを追加しました。数字のつながりはPythonモデルを一つの正本として機械検算。物語のためのデータでも、都合よく数字を曲げない。それがデータの流儀です。

### 05 Company_Twin_Agent（03:04–04:08）

資料がそろうと、検証官ツインが会社の分身を起動します。通常の仕事が進む世界に、実験者が逸脱を一手だけ差し込み、その後の社員や顧客の行動を観察します。直近の広域実行は、二十の場面から六十の分岐世界をつくりました。全ての事実は一行ずつ記録され、ハッシュで連鎖します。結果は、システムが拒否した世界が二十七。逸脱が通って契約まで到達した世界が十。途中で止められた世界が六。期間内に決着しなかった世界が十七でした。興味深いのは、止まった世界では、いずれも人が規程を引用して制止していたことです。ただし、ツインは一度の実験を完全な答えとは呼びません。見つけた経路を記録と再現手順つきで示し、網羅性や将来予測を誇張しない。検証可能な小さな発見を重ね、次の検査設計を鍛えていきます。

### 06 demo_video（04:08–04:40）

最後に、映像編集者のビオが受け取ります。設計や検証がどれほど優れていても、仕組みを知らない人に伝わらなければ、次の判断にはつながりません。ビオは複雑な技術を八秒の断片へ分け、ひとつの画面には、ひとつの論点だけを置きます。ナレーション、図解、音楽を同じ時間軸に並べ、技術の中身を削らずに、初めて見る人にも追える物語へ変えていきます。

### 07 Epilogue（04:40–05:04）

記録係が昨日を残し、設計士が証跡を整え、資料管理官が現実を支え、検証官が穴を探し、映像編集者が意味を届ける。五人の仕事は、ばらばらなツールではなく、学び続ける一本のループです。次の朝、リポジトリ街は、また一段だけ賢くなっています。

## 映像方式

- 1280×720、24fps、全シーン8秒固定。
- 5つの人物は色・アイコン・動きで識別する。
- 実写素材の反復ではなく、リポジトリ内容に合わせたモーショングラフィックスで38場面を個別に構成する。
- BGMは既存のオリジナル音源をループし、ナレーションを優先した音量にする。
- 今回の完成版ナレーションは、リポジトリ情報を外部送信しないPC内蔵の`Microsoft Haruka`で生成する。OpenAI TTS `cedar`用スクリプトは、明示承認後に差し替えられるよう別途残す。
